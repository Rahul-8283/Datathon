# Phase 3: Relational CRUD APIs & Data Models (Detailed Implementation Guide)

## 1. Overview and Core Objectives
In Phase 3, we build the central nervous system for our structured data. While our platform relies heavily on graph networks and vector searches, the "source of truth" for legal records, officer assignments, and basic incident logs lives in the relational PostgreSQL database managed by Supabase.

The objectives of this phase are to:
1. Define the relational schema using SQLAlchemy ORM.
2. Setup Alembic to track schema changes (migrations) automatically.
3. Build the FastAPI RESTful endpoints to Create, Read, Update, and Delete (CRUD) these records.
4. Consume these endpoints on the frontend to display a searchable, paginated "Cases Ledger."

---

## 2. Directory Structure & File Architecture
We will adopt a strictly layered architecture in the backend to separate concerns. This prevents our API router files from becoming cluttered with database logic.

```text
Datathon/
└── backend/
    ├── alembic/             # Auto-generated by alembic init
    ├── alembic.ini          # Alembic configuration
    ├── api/
    │   └── v1/
    │       └── cases.py     # FastAPI Route definitions (The "Controller")
    ├── crud/
    │   └── crud_case.py     # Database execution logic (The "Repository")
    ├── models/
    │   └── case.py          # SQLAlchemy ORM definitions (The "Database Schema")
    └── schemas/
        └── case.py          # Pydantic models (The "API Validation Schema")
```

## 3. Implementation Steps

### 3.1 Defining the Database Schema (SQLAlchemy Models)
- Create `backend/models/case.py`.
- Define a `Case` class that inherits from the `Base` created in Phase 1.
- Add essential columns: `id` (UUID, primary key), `fir_number` (String, unique), `date_reported` (DateTime), `district` (String), `status` (String: Open/Closed/Cold), and `description` (Text).
- Add auditing columns: `created_at` and `updated_at`.

### 3.2 Defining the API Schema (Pydantic Models)
- Create `backend/schemas/case.py`.
- Define a `CaseBase` class with standard fields.
- Define a `CaseCreate` class (inherits from Base) for incoming POST requests.
- Define a `CaseResponse` class (inherits from Base, adds `id`, `created_at`) with `model_config = ConfigDict(from_attributes=True)` so Pydantic can parse SQLAlchemy objects into JSON.

### 3.3 Database Operations (CRUD Layer)
- Create `backend/crud/crud_case.py`.
- Write asynchronous functions:
  - `get_case_by_id(db_session, case_id)`
  - `get_cases(db_session, skip, limit)` -> For pagination.
  - `create_case(db_session, case_in: CaseCreate)` -> Adds the object to the session, commits, and refreshes.
  - `delete_case(db_session, case_id)`

### 3.4 API Routers (FastAPI Endpoints)
- Create `backend/api/v1/cases.py`.
- Initialize an `APIRouter(prefix="/cases", tags=["Cases"])`.
- Create endpoints:
  - `GET /` -> Returns a list of cases. (Inject the DB session and pagination query params).
  - `POST /` -> Creates a new case. (Inject the DB session and `CaseCreate` body).
- **Crucial:** Secure these endpoints by injecting the `get_current_user` dependency from Phase 2 to ensure only authenticated officers can view or alter records.

### 3.5 Database Migrations (Alembic)
- Run `alembic init alembic` in the `backend/` directory.
- Edit `alembic.ini` to pull the `DATABASE_URL` from your environment.
- Edit `alembic/env.py` to import your `Base` and set `target_metadata = Base.metadata`.
- Run `alembic revision --autogenerate -m "Initial case table"`.
- Run `alembic upgrade head` to push the new tables up to your Supabase Postgres instance.

### 3.6 Frontend Integration (The Cases Ledger)
- In the React frontend, create a new page component `CasesLedger.tsx`.
- Create an API service file `services/api.ts` configured with Axios. Ensure it automatically attaches the user's Supabase JWT to the `Authorization` header.
- Create a `useEffect` hook that fires `axios.get('/api/v1/cases')` on component mount.
- Display the resulting array of JSON objects in a sleek, dark-themed HTML `<table>`. 
- Add a "Create Case" modal/form that sends a POST request to the backend and dynamically updates the table state upon success.

---

## 4. Key Considerations
- **Separation of Concerns:** Never pass a SQLAlchemy object directly to the client. Always return a Pydantic `CaseResponse` model to ensure strict JSON formatting and prevent leaking hidden database columns (like internal IDs or passwords).
- **Pagination:** Do not return all cases at once. Always implement `skip` and `limit` parameters on your GET routes.
- **Timezones:** Store all `DateTime` fields in UTC. Let the React frontend convert UTC to the user's local timezone (IST) for display.

---

## 5. Definition of Done & Verification Strategy
You know Phase 3 is complete when:
1. You can inspect your Supabase dashboard and see the newly created `cases` table generated by Alembic.
2. You can use the FastAPI Swagger UI (`http://localhost:8000/docs`) to manually POST a new case and GET it back.
3. You can navigate to the "Cases Ledger" tab in the React dashboard and see the case you just created rendered in the table.
4. Attempting to access `/api/v1/cases` without logging in results in a `401 Unauthorized` error.
